## 发现

### 1. [CRITICAL] 工具调用被自动批准，没有任何人工或策略确认

- 规则：`MCP-02` · 来源：`sample-dangerous-mcp.json`
- 说明：[filesystem] autoApprove/alwaysAllow 对全部工具放行，等于把 agent 的决策权直接交给模型输出。
- 证据：`true`
- 修复：关闭全量自动批准；改为按工具白名单 + 危险动作强制审批。

### 2. [CRITICAL] MCP 服务以 shell 解释器 -c 方式启动，等价于任意命令执行

- 规则：`MCP-03` · 来源：`sample-dangerous-mcp.json`
- 说明：[shell] 命令字符串由模型或配置拼接，一旦可被影响就是远程命令执行。
- 证据：`bash -c npx -y mcp-server-shell@latest sk-***redacted*** 0`
- 修复：改为可执行文件直接启动；确需脚本时固定参数、禁止拼接外部输入。

### 3. [CRITICAL] 凭据以明文形式写在 mcp.json 的 env/headers 中

- 规则：`MCP-05` · 来源：`sample-dangerous-mcp.json`
- 说明：[shell] 环境变量 OPENAI_API_KEY 直接包含真实凭据；该文件通常随项目同步、备份、进日志。
- 证据：`"OPENAI_API_KEY": "sk-***redacted***"`
- 修复：改用运行时注入的环境变量或密钥管理服务；mcp.json 中只保留 ${KEY} 占位符。

### 4. [CRITICAL] 文件系统服务暴露了过宽的根目录

- 规则：`MCP-07` · 来源：`sample-dangerous-mcp.json`
- 说明：[filesystem] 根目录 / 让 agent 可读写本机任意路径（含凭据、代码、系统文件）。
- 证据：`/`
- 修复：把根目录收敛到项目内子目录，并配置只读 + 路径前缀校验。

### 5. [CRITICAL] 数据库连接串内嵌明文口令

- 规则：`MCP-10` · 来源：`sample-dangerous-mcp.json`
- 说明：[prod-db] agent 一旦能读该配置，就能直连生产库；写权限更会绕过业务规则。
- 证据：`postgres://ops_admin:***@db.prod.internal:5432/billing`
- 修复：使用 IAM/短期令牌或仅授予只读账号；口令放密钥服务，不放配置。

### 6. [CRITICAL] 源码中硬编码了真实凭据

- 规则：`PY-05` · 来源：`sample-python-agent.py`
- 说明：密钥进入源码就会进入 git 历史、日志与备份；轮换成本远高于一次性修复。
- 证据：`L28: sk-***redacted***`
- 修复：立即轮换该密钥，改用环境变量或密钥管理服务；加入 secret 扫描门禁。

### 7. [HIGH] 远程 MCP 使用明文 HTTP 传输

- 规则：`MCP-09` · 来源：`sample-dangerous-mcp.json`
- 说明：[remote-kb] 工具描述与返回内容可被中间人篡改，进而影响 agent 决策（工具投毒）。
- 证据：`http://kb.internal:8080/mcp`
- 修复：改用 HTTPS 并校验证书；对远程 MCP 增加响应签名/固定哈希。

### 8. [HIGH] 关闭了 Node 的 TLS 证书校验

- 规则：`MCP-11` · 来源：`sample-dangerous-mcp.json`
- 说明：[shell] NODE_TLS_REJECT_UNAUTHORIZED=0 使该进程所有 HTTPS 请求都不再验签。
- 证据：`NODE_TLS_REJECT_UNAUTHORIZED=0`
- 修复：移除该变量；如需自签证书，显式传入 CA 而不是关闭校验。

### 9. [HIGH] subprocess 以 shell=True 执行命令

- 规则：`PY-01` · 来源：`sample-python-agent.py`
- 说明：命令字符串交给 shell 解释，任何拼接进命令的模型输出都可以逃逸成任意命令。
- 证据：`L8: subprocess.run(command, shell=True`
- 修复：改为 shell=False + 参数列表；确需 shell 时使用固定命令白名单。

### 10. [HIGH] 动态执行模型/用户可控的代码

- 规则：`PY-03` · 来源：`sample-python-agent.py`
- 说明：eval/exec 会把字符串当代码运行，等于把执行权交给输入方。
- 证据：`L12: eval(`

### 11. [HIGH] 关闭了 HTTPS 证书校验

- 规则：`PY-06` · 来源：`sample-python-agent.py`
- 说明：关闭校验后，工具返回内容可被中间人替换，进而篡改 agent 行为。
- 证据：`L18: verify=False`
- 修复：恢复证书校验；自建 CA 时显式传入 CA 包而非关闭校验。

### 12. [HIGH] SQL 由字符串拼接/f-string 构造

- 规则：`PY-08` · 来源：`sample-python-agent.py`

- 证据：`L20: cursor.execute(f"UPDATE orders SET refunded=1 WHERE id={order_id}`
- 修复：改用参数化查询；数据库账号最小权限且只读为主。

### 13. [HIGH] 发现 4 个工具定义，但没有接入策略门

- 规则：`PY-16` · 来源：`sample-python-agent.py`

- 证据：`tool decorators: 4, policy references: 0`

### 14. [HIGH] 存在命令执行类工具函数
